# ミニTwitter (X) クローン

HTML1枚 + [Supabase](https://supabase.com) で作った、Xっぽいミニアプリです。
Singularity Society BootCamp のもくもく会で、Web開発の基礎を学びながら作りました。
最優先は「完成」より「自分で理解すること」。

## できること
- ログイン（Google認証）
- 投稿・下書き（下書きは自分だけ）
- 公開タイムライン / フォロー / ホームタイムライン（フォロー中だけ）
- いいね ❤️ / コメント 💬
- プロフィール（表示名・自己紹介・アイコン画像アップロード）
- ユーザー検索 / 他人のプロフィール表示
- スマホ・PC両対応

## 作り方：2つのフェーズ（ここを切り分けて見てほしい）

### 前半：教材どおり（第1〜12章）
[Singularity Society の教材](https://singularitysociety.github.io/societys_statement/development/twitter_supabase/README.html)（Twitterクローンで学ぶWeb開発）の第1〜12章を、**説明書どおりに1章ずつ**進めました。
ログイン → 投稿 → RLS → 公開タイムライン → フォロー → ホーム → スケールの話まで。ここは「自分で考えた」というより、教材に沿って理解しながら作った部分です。

### 後半：自分で考えた拡張（教材の外）
ここからは教材には無く、**「Xに近づけたい」と自分で考えて**作った部分です（いいね・コメント・プロフィール・検索・他人のプロフィール・画面分け・スマホ対応・デモ配慮 など）。
このとき意識した進め方：
- いきなり「これとこれをやりたい」ではなく、**「こういうことを実装したい。世の中（GitHub）からおすすめの標準を探して」** と指示する
- **ゴールとフェーズに分け、一気に勝手に物事を進めないよう**に指示する
- 各機能で**一部は自分の手も動かし、プレビューで実際の画面を確認**しながら進める

## 技術
- フロント: HTML 1枚（フレームワークなし、ハッシュ・ルーティングで画面分け）
- バックエンド: Supabase（認証 / DB / ストレージ / RLS）

## いちばんの学び：RLS（行レベルセキュリティ）
この教材の背骨は「**そのデータは誰のもの？**」。
守りはフロントの見た目ではなく、**DB側で強制**する（＝他人のデータは見えない・消せない）。
`auth.uid() = user_id` のポリシーで「自分の行だけ」を実現しています。

## 作り方の学び（バイブコーディング）
非エンジニアがAIにざっくり「やりたいこと」を投げると、理想と違うものができたり、曖昧なまま進んで物事が進まないことが多いです。
今回うまくいったのは、次の進め方でした。

- **コア機能を決めて、ゴール設計とフェーズ分けをし、必要な機能を正確に実装していく**（AIを先生役にすると一緒に考えて進めてくれる）
- 機能を実装するたびに**一部は自分の手を動かす** ／ **プレビューで実際の画面を見ながら**進める → 大きな失敗が少なく、結果的に早い
- UI・デザインの指示は、**GitHubの既存（標準）を参照させて**分かりやすく伝える（AIが思う「いいデザイン」と自分の「いい」にはズレがある）
- AIは横に逸れがちなので、**最初のゴール設計とフェーズ分け**で道を決めておく
- 複数のAIを使い分けるより、**Claude Code に一元化**したら「今なにが実装されているか」が見えて、進みやすく・正確になった
- デザインは、GitHubで“すごい人が作ったデザイン・機能”を見て「これはいいな」と**カタログから選ぶ感覚**で（AIが勝手に作るデザインは「なんじゃこりゃ」も出る）

「Xで見るような一撃で理想が出る」もありますが、現時点ではこの方法が確実だと感じました。
