# ミニTwitter (X) クローン

HTML1枚 + [Supabase](https://supabase.com) で作った、Xっぽいミニアプリです。
Singularity Society BootCamp のもくもく会で、Web開発の基礎を学びながら作りました。
最優先は「完成」より「自分で理解すること」。

## 🔗 触ってみる
https://shoujiki-panman.github.io/minitwitter-x/

- Googleでログインして使えます。
- 試したあとは、プロフィール画面の「自分のデータを消す」で足跡を消せます。
- 表示名はメール名ではなく「パン仲間◯◯」が自動で付きます。

## できること
- ログイン（Google認証）
- 投稿・下書き（下書きは自分だけ）
- 公開タイムライン / フォロー / ホームタイムライン（フォロー中だけ）
- いいね ❤️ / コメント 💬
- プロフィール（表示名・自己紹介・アイコン画像アップロード）
- ユーザー検索 / 他人のプロフィール表示
- スマホ・PC両対応

## 技術
- フロント: HTML 1枚（フレームワークなし、ハッシュ・ルーティングで画面分け）
- バックエンド: Supabase（認証 / DB / ストレージ / RLS）

## いちばんの学び：RLS（行レベルセキュリティ）
この教材の背骨は「**そのデータは誰のもの？**」。
守りはフロントの見た目ではなく、**DB側で強制**する（＝他人のデータは見えない・消せない）。
`auth.uid() = user_id` のポリシーで「自分の行だけ」を実現しています。

## 作り方の学び（バイブコーディング）
非エンジニアがAIにざっくり「やりたいこと」を投げると、理想と違うものができたり、曖昧なまま進んで物事が進まないことが多いです。
今回うまくいったのは、次の進め方でした。

- **コア機能を決めて、ゴール設計とフェーズ分けをし、必要な機能を正確に実装していく**（AIを先生役にすると一緒に考えて進めてくれる）
- 機能を実装するたびに**一部は自分の手を動かす** ／ **プレビューで実際の画面を見ながら**進める → 大きな失敗が少なく、結果的に早い
- UI・デザインの指示は、**GitHubの既存（標準）を参照させて**分かりやすく伝える（AIが思う「いいデザイン」と自分の「いい」にはズレがある）
- AIは横に逸れがちなので、**最初のゴール設計とフェーズ分け**で道を決めておく

「Xで見るような一撃で理想が出る」もありますが、現時点ではこの方法が確実だと感じました。

```
これから〇〇を作ります。いきなり実装せず、次の順で進めてください：

③ GitHub等の標準的な既存事例を参考に（合えばベースにする）

⑤ 要所は私にも書かせて、「なぜそうするか」を説明
⑥ 各フェーズ末に「学び」を1〜2行で記録
優先順位は「コア機能(ユーザー価値) ＞ セキュリティ ＞ 使いやすさ(UX) ＞ デザイン」。
まずは “全体ゴール” と “フェーズ案” だけ出して、私の確認を待ってください。実装はそれからで。
```
